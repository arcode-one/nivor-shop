# SEO NIVØR

## Что реализовано

- Статическая генерация HTML через Vue SSR на этапе сборки: главная, три страницы моделей, корзина, оформление, настоящая страница 404. На хостинге не нужен Node.js.
- На каждом маршруте свой title, description, canonical, robots, Open Graph и Twitter Card. При переходах внутри Vue метаданные заменяются, включая удаление товарной разметки на служебных страницах.
- Четыре индексируемых URL: `/`, `/headphones/one/`, `/headphones/air/`, `/headphones/studio/`. Хлебные крошки, ссылки с главной и из подвала, взаимные ссылки моделей.
- `noindex, follow` в исходном HTML корзины, оформления и 404. Robots.txt не запрещает их обход: робот должен прочитать noindex. Неизвестные адреса не перенаправляются на главную.
- Sitemap с четырьмя страницами и изображениями. Не добавляются служебные страницы, параметры цветов и искусственные даты обновления.
- JSON-LD: WebSite, Brand, CollectionPage, ItemList, FAQPage, WebPage, BreadcrumbList, ProductGroup и пять Product-вариантов на странице каждой модели.
- Каталог и FAQ используются одновременно интерфейсом и микроразметкой. Canonical цветовых вариантов указывает на страницу модели; ссылки `?color=...` выбирают соответствующий цвет после загрузки приложения.
- Готовые JPEG-превью 1200×630 для главной и каждой модели. PNG автоматически преобразуются в WebP; приоритет загрузки главного изображения повышен, нижние галереи загружаются лениво.
- Без JavaScript доступны основной текст, характеристики, FAQ и ссылки. Корзина и интерактивный выбор требуют JavaScript.

## Данные и режим проекта

В исходном подвале проект обозначен как **Concept Design & Development**. Поэтому режим по умолчанию — концепт. В метаданных и на новых страницах это указано явно. Product-разметка описывает демонстрационные модели, но не содержит коммерческих Offer, неподтверждённых отзывов, рейтингов и остатков. Она служит семантическим описанием, а не заявкой на торговые расширенные результаты.

Для подтверждённого действующего магазина задайте переменную `VITE_SITE_MODE=store`. Тогда в граф добавляются OnlineStore и предложения Offer с ценами RUB из `src/cart.ts`. Этот переключатель сам по себе не превращает демонстрационную форму в реальный магазин: перед коммерческим запуском нужны реальные каталог, наличие, контакты, доставка, возвраты и обработка заказов. В исходном проекте корзина локальная, а оформление имитирует подтверждение.

Не добавлены вымышленные GTIN/MPN, адрес, юридическое лицо, отзывы, сроки действия цен и географическое покрытие. После подтверждения этих данных можно расширить OnlineStore и Offer. Условия возврата/доставки нельзя выводить из одного рекламного слогана.

## Настройки сборки

Канонический адрес по умолчанию — `https://nivor.arcode-dev.ru/`, он соответствует `public/CNAME`.

Переменные окружения (локально `.env.local`, на CI — `env`):

```dotenv
VITE_SITE_URL=https://nivor.arcode-dev.ru/
VITE_BASE_PATH=/
VITE_SITE_MODE=concept
# Заполняются только значениями из соответствующих кабинетов:
# VITE_GOOGLE_SITE_VERIFICATION=...
# VITE_YANDEX_VERIFICATION=...
```

`VITE_SITE_URL` — полный HTTPS-адрес со всеми частями пути. Для GitHub Pages без своего домена пример: `https://username.github.io/Nivor/`, а `VITE_BASE_PATH=/Nivor/`. При смене домена согласуйте переменную, `public/CNAME` и настройки хостинга. Не размещайте секреты в VITE-переменных: они публичны.

Главные источники:

- `src/seo.ts`: URL, метаданные, JSON-LD, настройки подтверждения сайтов.
- `src/cart.ts`: модели, характеристики, цены, названия цветов и изображения.
- `src/content.ts`: FAQ, общий для страницы и JSON-LD.
- `scripts/prepare-images.mjs`: WebP и социальные превью.
- `scripts/prepare-pages.mjs`: статические HTML, sitemap, robots и 404.

## Проверка и публикация

```bash
npm ci
npm run build
npm run test:seo
npm run preview
```

Публикуется каталог `dist/`. На GitHub Pages `/headphones/one/`, `/cart/` и другие существующие маршруты обслуживаются из отдельных `index.html`, а неизвестные адреса — через `404.html` со статусом 404. Для другого хостинга настройте такую же обработку: нельзя возвращать главную с HTTP 200 на любой неизвестный URL. Vite preview — средство локального просмотра, не гарантия HTTP-поведения продакшена.

`test:seo` проверяет HTML всех маршрутов, уникальность метаданных, единственный H1/canonical, индексацию, структуру JSON-LD, соответствие вариантов каталогу, FAQ, существование изображений и sitemap. Тест включён в CI перед публикацией.

После выкладки владельцу домена остаётся:

1. Подтвердить сайт в Google Search Console и Яндекс Вебмастере; DNS-подтверждение не требует изменения кода, метатеги поддерживаются через переменные выше.
2. Отправить `https://nivor.arcode-dev.ru/sitemap.xml` в оба кабинета.
3. Проверить опубликованные страницы в URL Inspection и Rich Results Test; для полной семантической проверки использовать Schema Markup Validator. Предупреждения об отсутствии коммерческих Offer в режиме концепта ожидаемы.
4. Проверить HTTP 200 для четырёх индексируемых страниц, HTTP 404 для несуществующего адреса, HTTPS и доступность WebP/JPEG для роботов.
5. Собирать полевые данные Core Web Vitals и поисковых запросов. Высокая оценка или место в поиске не гарантируются наличием микроразметки.

Кабинеты поисковиков не подключены, sitemap наружу не отправлялся. Изменения сами по себе не публикуют сайт.

## Основания решений

- [Google: JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) — доступный исходный HTML и обход ссылок.
- [Google: варианты товаров](https://developers.google.com/search/docs/appearance/structured-data/product-variants) — ProductGroup, hasVariant, variesBy и выбираемые URL вариантов.
- [Google: правила структурированных данных](https://developers.google.com/search/docs/appearance/structured-data/sd-policies) — разметка должна соответствовать содержимому страницы.
- [Google: Product snippets](https://developers.google.com/search/docs/appearance/structured-data/product-snippet) — товарные расширенные результаты и требования к данным.
- [Google: обновления документации](https://developers.google.com/search/updates) — FAQPage сохранён для семантики; выдача FAQ-блока Google не обещается.
